# livesplit-core in Lockpick

Lockpick uses [livesplit-core](https://github.com/LiveSplit/livesplit-core) (MIT or Apache-2.0, the engine of
LiveSplit One) as its timer engine, so a runner needs no other timer: LiveSplit's own timing and comparisons,
`.lss` files read and written exactly as LiveSplit does, and LiveSplit's layout drawn on Lockpick's overlay and OBS
page. Lockpick's own split triggers (docs/RUNS.md) still decide *when* to split; livesplit-core keeps the times.

## Trial (2026-10-16, branch `spike/livesplit-core`)

| What | Result |
|---|---|
| Source | `extern/livesplit-core`, a submodule pinned to `eb9d284` (2026-10-12) |
| Toolchain | Rust 1.99.1 (livesplit-core needs ≥ 1.96), MSVC target |
| C API, timer + `.lss` + software rendering | `livesplit_core.dll` 6.3 MB, 38 s to build from cold |
| … plus the WebAssembly autosplitting runtime (wasmtime) | 21.3 MB, 2 min 48 s from cold |
| C# bindings | generated by livesplit-core's `bind_gen` (`--features software-rendering`): one file, ~11 000 lines, `DllImport` |
| Parse a community file | "Resident Evil - Jill - Bad Ending - NMG.lss": parsed as LiveSplit, 16 segments |
| Time on game time set from outside | start, game time set to 20.9 s / 75.25 s with a split at each, then 90 s: split index 2, game time 90 |
| Draw LiveSplit's default layout | 300×500 RGBA by the software renderer: title, the 16 splits with King Henry 0:20 and Yawn 1 1:15, the current split highlighted, the timer at 1:30.00 |
| Save | a valid `.lss` (16 segments, attempt count 1) |
| Total | 103 ms for all of it |

Gotcha: `SoftwareRenderer.Render`'s stride is in **pixels**, not bytes (a byte stride overruns the buffer).

## Decisions

- **No autosplitting runtime in Lockpick.** Lockpick splits with its own triggers, so it ships the 6.3 MB engine.
  The RE1 autosplitter in livesplit-core's WebAssembly format (from Lockpick's verified addresses) is a separate
  build for LiveSplit users and the community.
- **The engine follows Lockpick's run** (RunService): a new attempt resets and starts the livesplit-core timer on
  game time with its own count paused; every split, undo, skip and reset is mirrored, and the game time is set from
  the game's clock every poll — the same mapping as LiveSplit's Drive mode.
- **Bindings are committed** (regenerated with the submodule); the native library is built from the pinned
  submodule by the build (`cargo build`, incremental) and copied next to Lockpick.
- **Licenses:** livesplit-core is MIT or Apache-2.0; its notice ships with Lockpick (THIRD-PARTY-NOTICES).

## Plan

1. `src/Lockpick.LiveSplit`: the bindings (generated code, no analyzers), the native build, a small `LiveSplitTimer`
   wrapper (load a split set or a file, mirror the run, render, save).
2. The overlay's **LiveSplit timer** widget (LiveSplit's layout, drawn by livesplit-core) and the OBS page
   `/overlay/livesplit` (the same picture from the API).
3. Imported `.lss` files kept and saved through livesplit-core, losslessly (icons, history, comparisons).
4. CI and the release: the Rust toolchain and the submodule checkout.
5. Later: livesplit-core's comparisons and statistics in Lockpick's pages; the RE1 WebAssembly autosplitter.
